# 07. AI 작업 규칙

AI(Claude Code)가 이 저장소에서 작업할 때 지켜야 하는 행동 규칙이다.

## 작업 순서
1. 요청을 받으면 관련 규정 문서를 확인한다. 규정과 요청이 충돌하면 **작업 전에 사용자에게 알린다.**
2. 기존 코드의 구조·네이밍·스타일을 먼저 읽고 **그에 맞춰** 작성한다.
3. 작은 단위로 구현하고 빌드·테스트로 확인한다.
4. 완료 기준(`05-coding-conventions.md`)을 만족한 뒤 결과를 보고한다.

## 범위 통제
- 요청한 것만 구현한다. 부가 기능, 선제적 리팩터링, 불필요한 추상화를 추가하지 않는다.
- 요청과 무관한 파일을 수정하지 않는다. 필요해 보이면 제안만 한다.
- 새 의존성, 모듈 분리, 스키마 대규모 변경, 외부 서비스 도입은 **사용자 승인 후** 진행한다.

## 사용자 확인이 필요한 행동
- 파일·데이터 삭제, DB 마이그레이션 적용, 의존성 추가/변경
- `git push --force`, 브랜치 삭제, 히스토리 재작성 (일반 commit/push는 위임됨)
- 외부 서비스로 데이터 전송, 유료 API 호출, 

## 금지
- 비밀 값 생성·하드코딩·출력, 비밀 파일 커밋
- 기사 본문 저장, 규정 우회 (`06` 참조)
- 테스트를 지우거나 약하게 만들어 통과시키기
- 린트·보안 규칙을 끄는 방식의 해결
- 확인하지 않은 것을 완료했다고 보고하기

## 모를 때
- 추측으로 API·라이브러리 사용법을 쓰지 않고 공식 문서나 기존 코드를 확인한다.
- 요구사항이 모호하면 가정을 명시하고 사용자에게 질문한다.

## 규정 문서 유지
- 구조, API, DB, UI 정책이 바뀌면 같은 작업에서 해당 문서를 갱신한다. 규정이 부족하다고 판단되면 직접 보완하고 변경 내용을 보고한다.
- 문서는 간결하게 유지한다. 규칙이 늘면 오래된 항목을 정리한다.
- 응답은 한국어로 작성한다. 코드, 명령어, 경로, 오류 원문은 그대로 둔다.
